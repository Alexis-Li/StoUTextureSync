# StoUTextureSync：Substance 3D Painter → Unreal Engine 贴图同步

本文定义产品范围、功能要求和验收依据。产品处于设计与技术验证阶段，宿主兼容性和性能以目标环境中的测试结果为准。

## 1. 目标与范围

StoUTextureSync 将 Painter 中的纹理修改自动同步到 UE 已有 Texture 资产，使美术人员直接在 UE 场景中检查材质效果。

| 项目 | 基线 |
| --- | --- |
| 项目名称 | StoUTextureSync |
| 平台 | Windows |
| 宿主 | Painter 11.0；官方 Unreal Editor 5.7.4 与 Topia Engine 5.7.4 |
| 资产规模 | 常见工程约 9–18 张输出贴图 |
| 输出尺寸 | 按 Texture Set 默认 1K，允许显式设为 2K；裸模支持部位 Tile 覆盖；保持长宽比，长边为 1024 或 2048 |
| 服装 | 按独立材质对应 Texture Set，导出普通二维贴图 |
| 裸模 | 在 SP 中按 UDIM Tile 绘制，导出后映射为部位文件名，在 UE 中使用独立普通 Texture |
| 导出预设 | “兔皮鸭套装输出.spexp”，支持选择其他项目预设 |
| 工作机 | 32GB 系统内存；SP 与 UE 同开时常有较高内存压力 |
| 延迟目标 | 从最后一次有效修改结束到 UE 视口显示完整最新结果，目标为 5 秒以内 |

自动与手动同步使用相同的输出规格。尺寸限制针对输出文件，任一维度不得超过 2048；SP 工程内部的工作分辨率由原有制作流程管理。9–18 张是工程输出规模，每次同步的范围由发生变化的 Texture Set、Tile 和已启用绑定决定。单 Tile、单 Texture Set 及多部位变化分别对照 5 秒目标测量，完整同步单独报告耗时；适用范围以原型数据确定。

刷新期间允许各张贴图先后生效，完成后应呈现同一批次的最新结果。发布或重导入失败导致的持续不一致属于故障。

### 1.1 成功标准

- 首次配置后，常规绘制能自动更新 UE 中已有的贴图资产。
- 输出内容、通道和部位映射正确，原有材质引用与 Texture 导入设置保持稳定。
- 任务与缓存有明确上限，连续修改后最终结果能够追上 SP 当前内容。
- 故障能定位到具体阶段和文件，并有可执行的恢复步骤。
- 在实际工作机上测量端到端延迟、SP 交互停顿及资源增量。

### 1.2 功能边界

核心功能覆盖 SP 导出、命名映射、本地文件发布和 UE 既有贴图更新。首次导入、材质连接和资产保存由用户在现有流程中完成。

插件保留 Master Material、Material Instance、贴图引用和非目标资产，不自动删除用户源贴图。版本控制、资产提交、模型及动画同步、UE 渲染画面回传、云端协作和游戏运行时同步不在产品范围内。HDR 环境与视角对齐属于独立的可选功能。

## 2. 使用流程

### 2.1 首次配置

1. 在 SP 打开并保存工程，在插件面板选择预设、Texture Set 和输出尺寸。
2. 设置 SP 工程位置、本地源贴图目录、UE 工程位置与 UE 内容目录。裸模配置 Tile 到部位名称的映射，预览最终文件清单。
3. 首次由用户将最终命名的源图片导入所选 UE 内容目录，连接到项目原有材质。已有 Texture 则核对其源文件关联。
4. 在 UE 配置限定目录与扩展名的 Auto Reimport，关闭 Auto Create Assets 与 Auto Delete Assets。
5. 执行一次手动同步，检查目标资产、通道、法线方向、导入设置与材质表现，然后开启实时同步。

| 路径设置 | 用途 |
| --- | --- |
| SP 工程 `.spp` | 默认读取当前工程位置，用于识别和恢复对应配置 |
| 本地源贴图目录 | 最终图片发布位置，也是 UE Texture 的导入源位置 |
| UE 工程 `.uproject` | 区分不同 UE 项目的绑定配置 |
| UE 内容目录，如 `/Game/Characters/Coat/Textures` | 记录首次导入位置及预期资产路径 |

磁盘源文件与 UE 内容资产分别保存位置。填写或更改 UE 内容目录不会移动资产或修改其源文件关联；绑定变更后需要重新核对。

### 2.2 日常同步

```text
SP 纹理修改
  → 空闲等待，合并待处理变化
  → SP 官方导出到暂存目录
  → 校验输出，应用部位命名映射
  → 发布到固定源文件路径
  → UE 重导入已有 Texture
  → UE 原生视口显示更新
```

面板提供三项操作：

- **实时同步**：开启后在绘制空闲时自动处理变化；关闭后停止后续自动导出和发布。
- **立即同步**：立即处理启用绑定中待同步的变化，保持实时开关原有状态。
- **完整同步**：重新导出并发布所有启用绑定，用于收尾核对和故障恢复。

插件处理关闭操作后，尚未发布的自动任务失效。导出阻塞界面时，开关响应可能延后；导出返回后先处理待响应的控制操作，再校验任务有效性并进入发布。已经发布的文件和 UE 已开始的重导入可能继续生效。重新开启后合并处理积累的变化。

## 3. 功能要求

P0 为首个可用版本 M1 必需能力；P1 为生产使用前完善的能力；P2 为按收益选择的扩展。涉及宿主 API 的要求均需实际验证。

### FR-01：变化监听与调度（P0）

1. 使用官方 `TextureStateEvent` 记录受影响的 Stack、通道和 Tile，并定位对应 Texture Set。
2. 事件回调只记录状态并排程。能够可靠定位变化 Tile 时，使用 `exportList.filter.uvTiles` 限定范围，导出这些 Tile 的全部启用输出，以覆盖合成法线和打包图的间接依赖。合并所有受影响 Tile；范围不确定或涉及全局变化时扩大到对应 Texture Set，完整同步覆盖所有启用绑定。事件 Tile 标识到导出 UV 坐标的转换由 PoC-02 验证。
3. 同时只执行一个导出批次；每个绑定只保留最新的待处理状态。导出期间出现的新变化在该轮结束后重新检查。
4. 实时、立即和完整同步共用串行调度器。完整同步开始前合并过时的待处理请求。
5. 项目关闭、退出编辑、切换工程、绑定失效和插件卸载时作废相关任务。发布前校验工程身份、配置版本和任务版本。
6. 在 SP 可编辑且不忙碌时导出；以 `BusyStatusChanged` 等目标版本接口验证烘焙和计算期间的行为。
7. 记录绘制、图层参数、填充层、遮罩、材质参数与烘焙的事件覆盖；缺少自动事件的操作提供手动同步入口。

### FR-02：导出预设与命名（P0）

所有同步调用 `substance_painter.export.export_project_textures()`。图层合成、通道打包和图片编码由 SP 完成；插件传入预设资源、导出范围、尺寸与暂存路径，并处理输出校验、命名和发布。

优先使用 Painter 中安装的导出预设。插件配置保存可解析的预设资源标识，并检查资源存在性；相同显示名称不能视为同一资源。标识失效时列出可用候选，由用户重选后重新校验输出清单。需要自定义通道时，通过官方导出配置表达。

导出规格包括文件格式、位深、分辨率、通道来源及顺序、法线方向、颜色空间、Alpha、Padding 与输出启用状态。尺寸按 Texture Set 设置，默认 1K；裸模允许按部位 Tile 覆盖为 1K 或 2K，同一部位的启用输出共用尺寸。使用保持工程长宽比的长边限制，预览中显示最终像素尺寸。插件导出内容应与相同预设、相同参数下的 SP 手动导出结果一致。

#### 项目预设

“兔皮鸭套装输出.spexp”的静态内容包含以下 PNG 输出模板：

| 输出 | 文件模板 |
| --- | --- |
| Albedo | `T_$textureSet_Albedo(_$colorSpace)(_$udim)` |
| ARM | `T_$textureSet_ARM(_$colorSpace)(_$udim)` |
| Normal | `T_$textureSet_Normal(_$colorSpace)(_$udim)` |
| Emissive | `T_$textureSet_Emissive(_$colorSpace)(_$udim)` |

预设还包含 `AO_Mixed` 与 `Normal_DirectX` 标记。实际 RGB / Alpha 布局、位深、颜色空间及输出启用行为由 PoC-03 在 SP 11.0 中加载核对。通道校验需区分文档通道、烘焙图与合成输出；ORM 的 AO / Roughness / Metallic 顺序与 AoMetalRough 的 AO / Metallic / Roughness 顺序不同，ARM 文件名本身不足以确定其布局。

#### 文件命名与部位映射

每个 Texture Set 独立选择命名模式：普通输出保留预设文件名，按需移除已识别的末尾 Tile 后缀；部位映射使用角色前缀、导出部位与 Tile 到目标部位的对应关系。同一工程中的服装与裸模分别配置。移除后缀后仍须保证输出唯一。

部位映射以显式绑定的 Texture Set、Tile 和预设输出为依据，按 `T_{角色前缀}_{目标部位}_{贴图类型}{颜色空间后缀}.{扩展名}` 生成最终文件名。角色前缀可留空，对应分隔符随之省略；不从 Texture Set 名中的下划线猜测字段。通过预设模板与预计输出清单建立对应关系，无法唯一解析时阻止发布并提示修正配置。

现有 `C00_Body_UDIM_Rename.bat` 提供以下项目样例：

| SP Tile | 目标部位 |
| --- | --- |
| 1001 | Face |
| 1002 | Body |
| 1003 | Arm |
| 1004 | Leg |
| 1005 | Nail |

例如 `T_C00_Body_Albedo_1001.png` 发布为 `T_C00_Face_Albedo.png`，`T_C00_Body_ARM_1003.png` 发布为 `T_C00_Arm_ARM.png`；带颜色空间的 `T_C00_Body_Albedo_sRGB_1001.png` 发布为 `T_C00_Face_Albedo_sRGB.png`。贴图类型、颜色空间后缀和扩展名按预设输出保留。前缀与部位映射均可配置。

命名转换在暂存阶段完成。预检查同时验证导出原名和最终发布名；未知 Tile、名称不匹配或多个输出指向同一最终文件时阻止发布。后续同步更新相同目标文件。修改映射后重新核对绑定，旧源文件由用户管理。

### FR-03：预检查与文件发布（P0）

1. 用 `list_project_textures()` 生成预计输出清单，检查配置缺失、输出重名、最终路径冲突、目录越界及多写入者冲突。
2. 每批导出到独立且不受 UE 监控的暂存目录。检查 API 状态、实际清单、格式、尺寸、文件大小及输出完整性。
3. 默认仅 Success 可发布；Cancelled、异常或未知 Warning 阻止发布并显示原因。结果清单必须对应本批新文件。
4. 整批校验通过后逐文件发布，保证 UE 读取到完整文件，并能触发既有资产重导入。优先验证目标同卷、监控范围外的完整临时文件原子替换；最终方式须通过 PoC-01。无法兼顾文件完整性与可靠监听时评估路线 B，由 UE 执行端协调重导入。
5. 文件占用导致替换失败时有限次重试。记录每个文件的结果、批次版本、尺寸和哈希；批次清单保存在插件自己的存储位置。
6. 导出或校验失败时目标文件保持原样。发布中途失败时标记“部分发布”、暂停自动任务并保留本批完整暂存输出及逐文件清单。在工程、配置和任务版本仍有效时可重试未完成文件；内容已变化或缓存不可用时重新完整同步。单文件原子替换不提供跨文件事务。
7. 自动同步仅在磁盘目标文件存在且当前内容与本批输出一致时跳过发布。去重依据实际目标内容，不能仅依据上一批导出哈希；目标被删除、还原或外部修改后应重新发布。完整同步绕过去重并重新发起发布。UE 是否因此重导入由 PoC-05 验证。
8. 缓存清理仅处理插件创建并能识别的文件，设置容量上限和清理策略。

### FR-04：UE 资产更新（P0）

源图片通过 UE 原生 Auto Reimport 更新已有普通 Texture。材质继续引用原来的 Texture 资产。

首次配置应核对最终源文件路径、目标资产以及共享该源文件的其他引用。目录监控可能更新所有关联资产；路线 A 依靠用户核对 UE 内的实际关联，SP 端负责文件路径与配置校验。UE 工程与内容目录用于隔离配置和展示预期资产；实际资产类型、源文件关联及当前打开的 UE 工程由用户在 UE 中核对。

UE 配置限定监控目录和扩展名，关闭 Auto Create Assets 与 Auto Delete Assets。联合测试 Import Threshold Time、重启检测设置及 Use Less CPU when in Background，给出适用于前台绘制 SP、后台运行 UE 的设置。

重导入须保持材质引用及 Texture 的 sRGB、Compression Settings、LOD、Mip、源文件关联等现有设置。路线 A 在宿主测试中核验；路线 B 可读取并报告差异。

路线 A 的面板状态止于“文件已发布，UE 状态未知”。“UE 导入完成”需要路线 B 返回与资产、文件和批次匹配的结果。

### FR-05：性能与资源（P0；监控增强 P1）

端到端延迟包含 SP 防抖、导出、文件发布、UE 监听等待、重导入和画面生效。以 1 秒空闲等待作为原型起点，记录并联合调整 UE 实际监听阈值，目标为 5 秒以内。两个等待阶段共同占用延迟预算；PoC-04 根据阶段耗时分配预算，分别报告局部和多部位更新的瓶颈。

单次 SP 界面停顿单独测量。插件取消作用于排队阶段与导出返回后的发布校验，不依赖中断正在执行的导出调用。SP 原生取消、导出进度窗口及 Qt 事件处理行为由 PoC-02 验证。自动同步应保持 SP 绘制焦点；测量连续落笔是否中断，发现超出交互阈值后暂停或减少后续任务。性能调整保持绑定的输出规格。

队列、缓存和常驻数据有界，不持续保存大尺寸解码贴图副本。连续错误、严重分页或明显交互停顿时暂停自动同步，并保留手动恢复入口。

P1 根据实测收益增加可用内存、提交量、进程占用及显存监控。阈值来自实际工作机，自动暂停可由用户调整。路线 A 的 UE 导入耗时由测试采集。

### FR-06：工程配置与绑定（基础 P0；高级管理 P1）

每个工程保存独立配置，包含：

- 工程身份、SP 文件位置、UE 工程位置和内容目录。
- 本地源贴图目录、预设资源及输出规格。
- 多个 Texture Set 的启用状态、输出范围、尺寸与部位覆盖及暂停状态。
- 各 Texture Set 的命名模式、部位映射及导出原名到最终文件名的对应关系。
- 最终源文件与预期 UE Texture 的绑定。
- 空闲等待、日志和缓存设置。

首版由面板读写本地 JSON。工程身份与路径分别维护，未保存工程先保存再绑定。M0 核对 SP 11.0 的 `project.get_uuid()` 可用性及重开、移动、另存为和复制后的身份语义；满足要求时使用宿主身份，否则使用插件专属 Metadata ID 或由用户显式关联本地配置。采用 Metadata 时只保存身份与必要版本信息，随用户保存工程持久化。

另存为、复制配置、Texture Set 重命名或路径变化后重新校验绑定。相同身份出现在多个路径时暂停自动发布，待用户选择沿用绑定或创建独立配置后恢复，避免工程副本意外覆盖相同目标。

多个实例对同一目标实行写入互斥。发布期间持有互斥并重新核对目标所有权；优先采用进程退出后自动释放的系统锁。若使用锁文件，应核验持有者是否仍存活，避免 PID 复用或仅凭超时误接管。异常退出后可恢复写入，仍在活动的写入者冲突应阻止发布。

重新打开工程时恢复有效配置，自动运行状态的默认处理见 §7。高级批量编辑与自动发现按实际需要扩展。

### FR-07：状态与恢复（基础 P0；诊断增强 P1）

基础状态包括等待修改结束、待同步、导出中、发布中、文件已发布、部分发布、失败和已暂停。路线 B 增加等待 UE 回执及 UE 完成状态。

日志记录工程、Texture Set、预设、目标文件、批次、各阶段耗时与错误原因。旧任务不得覆盖新结果；只有整批达到当前阶段的完成条件才记录该阶段成功。

恢复覆盖导出取消、文件占用、磁盘满、无权限、缓存丢失、路径移动、SP 中断和 UE 离线。优先通过完整同步恢复。路线 A 在 UE 重启后若仍需手动重导入，必须明确恢复步骤并据此评估路线 B。

### FR-08：SP 面板（基础 P0；高级功能 P1）

首版面板提供路径浏览、预设选择、Texture Set 绑定与命名模式、部位映射、最终文件及像素尺寸预览、Texture Set 尺寸与部位覆盖、配置保存与加载、实时开关、立即同步、完整同步和最近结果。

首次配置与日常操作可在面板完成。P1 增加高级预设编辑、批量绑定编辑、耗时诊断、缓存管理和日志入口。UE Auto Reimport 的首次设置通过配置指南完成。

### FR-09：HDR 环境对齐（P2）

在 UE 中选定模型位置，按需捕获 HDR 环境并加载到 SP，用于近似整体照明。验收图像投影、朝向、曝光与 SP 资源加载；不以 Lumen、阴影、反射和后处理完全一致为目标。

一键捕获和传递需要 UE 侧执行逻辑。先验证 Editor Utility / Python 与内置能力，再按接口需求决定组件形式。该功能独立启用，完成后释放捕获资源。

### FR-10：视角与绑定辅助（P2）

候选能力包括一键对齐视角、持续摄像机跟随、材质槽识别和批量绑定。涉及 UE 状态读取的能力由可选桥接组件提供。具体范围在扩展阶段确定。

## 4. 架构与工程约束

### 4.1 路线选择

首选路线 A：SP 插件负责导出与文件发布，UE 使用原生 Auto Reimport。组件少，安装维护成本较低；开发重点是调度、命名、发布和恢复。UE 的实际处理进度与结果不能直接从 SP 观测。

路线 B 增加 UE 执行端，负责接收批次通知、核对允许处理的资产、串行重导入、校验并回执。它提高定向控制和诊断能力，同时增加通信、生命周期与引擎兼容的开发维护成本。贴图仍通过本地文件传递。

在完成路线 A 的配置与频率调优后，出现以下情况时评估路线 B：

- 后台刷新、源路径关联或异常恢复仍不可靠。
- 导入调度造成无法接受的交互停顿或资源峰值。
- 产品需要可验证的 UE 处理结果。

用同样的资产与场景比较两条路线，分别记录成功率、延迟与资源开销。UE 执行端先以最小编辑器脚本验证，再决定是否需要 C++ 模块。路线 B 接管的文件范围应排除重复的 Auto Reimport 监听。若核心需求依赖路线 B，其组件随 M1 交付。

### 4.2 代码与宿主生命周期

调度、配置、映射、文件发布和版本管理放在不依赖 `substance_painter` 的 Python 核心中。事件、导出和 UI 放在 SP 适配层。

Painter API 在主线程调用；文件复制、哈希等独立工作可放在工作线程。`close_plugin()` 断开事件、停止计时器和线程并移除 UI，重复加载不得产生重复处理器。工程打开与进入可编辑状态分别处理。

遵守根目录及相关宿主的 `AGENTS.md`。文档与仓库示例使用相对路径，用户本地配置保存实际选择的位置。第三方预设与参考代码不复制进提案；需要复用受限内容时说明具体影响并评估替代方案。

### 4.3 产品位置与交付工具

| 形态 | 位置与所有权 |
| --- | --- |
| 路线 A | `substance-painter/plugins/StoUTextureSync/`；独立插件拥有 README 中英双版、CHANGELOG、LICENSE、版本及测试 |
| 路线 B | `composite/StoUTextureSync/`；包含 SP 与 UE 组件，产品元数据归 composite 根目录 |

首个 SP 项目按宿主规则补齐打包、版本和项目模板命令。进入开发时，依照 `docs/proposals/README.md` 将本提案内容迁往所属项目与问题记录。

## 5. 技术验证与验收

在实际 32GB 工作机上使用服装与裸模样本测试，记录精确宿主版本、预设、输出规模和可重复步骤。官方 Unreal Editor 5.7.4 与 Topia Engine 5.7.4 分别执行核心闭环、设置保持、后台刷新和故障恢复验证，使用相同素材对照；性能结果按引擎分别列出。未测试的宿主保持待验证状态。

### PoC-01：最小同步闭环

使用预先建立材质引用的 Texture，测试手动完整文件替换、原子替换和 SP 自动导出。记录 UE 目录监听事件，检查关闭自动创建 / 删除后的行为。分别测试 UE 前台与后台、后台 CPU 节流开启与关闭。

服装验证常规输出；裸模验证 Tile 映射、已有同名目标的再次更新，以及单个部位变化时的正确目标。检查资产保存并重开后的材质引用和导入设置。

通过条件：常规修改无需手动重导入，路径与资产对应正确，UE 不读取半写入文件，后台行为可复现且有可用配置。检查后台重导入的提示窗口是否抢夺 SP 焦点或打断落笔。

### PoC-02：SP 事件与交互

覆盖笔刷、图层参数、填充层、遮罩、材质参数与烘焙，记录事件身份和自动触发范围。验证事件 Tile 标识与 `uvTiles` 坐标的对应、跨 Tile 笔刷及全局图层变化，比较局部导出与完整导出的内容。测试防抖、串行、导出期间的新变化、工程切换及实时开关在不同阶段的行为。

测量导出期间的 SP 界面停顿、中位数和 P95，与尺寸、输出数量和图层复杂度对应。检查进度窗口、焦点、鼠标与手绘板连续落笔、原生取消以及开关输入到实际生效的时序，验证关闭操作生效后旧批次被发布前校验拦截。给出自动覆盖表、手动兜底操作和交互阈值建议。

### PoC-03：预设、输出与命名

由 SP 11.0 加载项目预设，核对通道、位深、颜色空间、Alpha、法线与输出启用状态。与相同参数的 SP 手动导出作内容对照，使用测试色块区分通道布局。

覆盖服装与裸模混合工程、单 Tile 服装输出、角色前缀为空或名称含多个下划线、颜色空间后缀、未知 Tile、最终文件重名、缺失通道及预设重名。验证中文工程与输出路径、中文预设名、跨资源库定位和失效资源重选。覆盖 Texture Set 尺寸、部位覆盖、非方图及超过上限的配置，验证预计清单、实际清单和最终发布清单一一对应。

重复导出未变化的内容，检查文件哈希及 PNG 元数据是否稳定，记录去重效果。验证目标文件被外部修改或删除后能够重新发布。

通过条件：错误配置被拦截，正确输出内容一致，已有目标可重复更新。

### PoC-04：端到端性能

| 维度 | 测试组合 |
| --- | --- |
| SP 工程 | 少图层 / 大量图层 |
| UE 场景 | 空白场景 / 正式角色与灯光场景 |
| 输出尺寸 | 1K / 2K |
| 输出规模 | 约 9 / 18 张；服装与裸模流程分别记录 |
| 同步方式 | 手动 / 空闲触发；单 Tile / 单 Texture Set / 多部位变化 / 完整同步 |
| UE 路线 | Auto Reimport；必要时增加显式重导入对照 |

先记录两宿主同开时的资源基线，再记录可用内存、系统提交量、分页、RAM / VRAM 峰值增量和插件常驻开销。记录每次实际变化和导出的贴图数量，分阶段测量 SP 防抖、导出、文件发布、UE 监听等待、重导入和画面可见时间，报告中位数、P95、最长延迟与超时原因。

局部和多部位修改分别对照 5 秒目标，完整同步耗时单独列出。超出目标时记录条件与瓶颈，提出调度或路线调整；需要缩小适用范围时由用户判断。连续多次更新后任务与资源应能回落；交互停顿按原型评估得到的阈值验收。

### PoC-05：故障与恢复

覆盖 SP 导出 / 发布中退出、第二张文件替换失败、文件占用、磁盘满、无权限、缓存丢失、Warning / Cancelled / 异常、未保存工程、工程另存为、工程复制、路径移动、映射冲突及多个实例写入同一目标。核对身份恢复、相同 ID 的副本隔离、锁释放或陈旧锁恢复，以及活跃写入者不会被误接管。

测试 UE 离线期间多批更新、重启检测开启 / 关闭，以及相同内容完整同步能否恢复 UE 结果。验证关闭实时开关后不产生新的自动发布。

通过条件：旧任务不覆盖新结果，部分发布能被识别，恢复后文件与 UE 显示正确，SP 工程及既有材质保持可用。记录路线 A 所需的额外手动恢复步骤，作为路线选择依据。

### PoC-06：显式重导入对照

路线 A 出现核心阻断时，实现最小的既有 Texture 定向重导入，用相同文件和场景对比成功率、延迟、内存、标脏行为、导入设置与材质引用。验证回执对应的批次，以及重复通知、过期通知和失败处理。

交付路线建议、日志和可重复测试步骤。

### 最终验收场景

| 场景 | 结果 |
| --- | --- |
| 服装绘制 | 停笔后自动更新原有材质，按 5 秒目标记录实际表现 |
| 裸模绘制 | Tile 输出按部位发布，多轮同步仍对应正确普通 Texture |
| 输出质量 | 默认 1K、例外 2K；内容与等参数 SP 导出一致 |
| 材质保护 | 材质结构、参数覆盖、贴图引用及非目标资产保持稳定 |
| 实时开关 | 关闭后停止后续自动发布，手动操作可用 |
| 配置恢复 | 重开和切换工程时加载对应绑定，失效路径被拦截 |
| 高资源压力 | 队列和缓存有界，可暂停并继续绘制 |
| 故障恢复 | 部分发布不报整批成功，执行恢复步骤后结果正确 |

## 6. 里程碑与任务

### M0：技术验证

完成 PoC-01 至 PoC-05，必要时执行 PoC-06；交付宿主行为、输出正确性、性能与故障记录。DEC-01 据此确定路线、适用范围、默认调度参数与组件布局。

进入 M1 的条件是闭环可用、输出正确、资源与交互表现可接受，剩余限制有明确处理办法。遇到核心阻断时优先解决阻断。

### M1：首个可用版本

交付 P0 功能、配置面板、现有预设引用、裸模命名、多 Texture Set 绑定、持久化、安全发布与恢复、UE 配置指南和核心测试。完成 REPO-01。路线 B 若为必要条件，同步交付 UE 组件。

### M2：生产完善

交付高级批量编辑与诊断，完善缓存和压力管理，完成正式场景中的长期运行与故障回归。

### M3：扩展

根据核心使用效果选择 HDR 环境、视角或绑定辅助功能。
